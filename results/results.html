Method: graph build

  • Data: latest 10-K of 35 companies (7 sectors x 5), fiscal years ending Nov 2025 - Sep 2026. EDGAR serves 10-Ks as HTML, so the official filing (plus Exhibit 13 for IBM, Wells Fargo) was printed to PDF with headless Chrome; the pipeline then reads only the PDFs.
  • Numbers without an LLM. Statement pages are scored (heading, year columns, key rows; handles split pages and MD&A look-alikes). A position-based parser clusters the right edges of numbers into columns tied to header years/dates, applies the printed scale and uses section headers for context. ~50 canonical metrics (config/ontology.yaml) with rule-based label mapping. Other year-column tables (~53K rows from notes/MD&A) are kept as labelled line items. Regex for the cover page, auditor report, headcount and signatures.
  • Prose relations with an LLM, grounded. Competitors, suppliers, customers, segments, acquisitions from Item 1 (Groq qwen3.8-27b, ~50 calls). Each must come with a verbatim quote + page; code checks the quote is on the page and contains the entity, else it is dropped. Entity resolution links "Advanced Micro Devices, Inc., or AMD" in NVIDIA's 10-K to the AMD company node.
  • Graph (NetworkX, ~80K nodes / 212K edges): Fact nodes (value, unit, verification) -> Metric, Company, Period (real end date, company's own fiscal label, rank, PRECEDES), Source (page, row text). Relation edges carry the fact holding their quote. Metric -DERIVED_FROM {formula}-> Metric. Accounting identities mark facts verified / conflicting (435 verified, 0 conflicting).
  • Extraction accuracy vs SEC XBRL (core statement facts of all 35 companies): first pass 80.9% -> 99.5% (607/610), 0 wrong values; the 3 misses are Capital One lines its statements do not print. Rules were fixed on these same filings, so this is a development number, not held-out.

Method: query

One LLM call (Groq gpt-oss-120b) turns the question into a JSON plan over 11 deterministic operators (get_fact, derive, yoy, related, find_line_item, filter, rank, aggregate, compute, compare, companies). The LLM never sees the PDFs and never writes a number. Operators log every fact node they touch; that set is the retrieved facts for precision/recall. One repair round on errors; abstain if the graph lacks the fact. Answers cite document, page and row/quote.

Method: benchmark

30 test questions (10 single-fact, 10 multi-hop, 10 cross-filing) + 14 dev questions (few-shot source, so dev scores are not meaningful). Drafted by Claude while reading the PDF pages, before the graph existed; spread over all sectors and filing parts (cover, statements, notes, Item 1 prose, auditor report), with deliberate traps: close calls (Intel vs NVIDIA assets), different fiscal calendars, a segment-note fact, a prose relation chain, a metric defined to exclude acquired IPR&D. Each item lists gold facts (company, metric/relation, period, printed value, document, page); derived answers are computed by script with the formula recorded. Verified by script: all 132 gold values/quotes are on the cited page, all 78 numeric gold facts equal XBRL; approved by Anmol and frozen in git before the first run. Scoring is deterministic (numbers 0.5%, percentages 0.1 pp, aliases for entities, sets, exact order).

Gaps: where it failed and why

  • T15 "Which companies share NVIDIA's auditor?" (first run) - missed Bank of America. Extraction (regex): BAC's report signature is an image and its text says "audited by PricewaterhouseCoopers" without "LLP". Fixed generally: known firm names without "LLP" and Item 14 / management-report phrasings -> auditor found for 35/35.
  • T30 "Who names TSMC as a foundry?" (first run) - missed Intel. Extraction (LLM recall): Intel calls TSMC both its main process competitor and a foundry it uses; on the 14K-character excerpt the model kept neither. Fixed generally: the model now reads both the whole excerpt and page-aligned 7K chunks and the union is kept (grounding still guards precision). Recall varies between views: on its first chunk Apple's 5 segments were returned as empty, which the union also fixed.
  • T18 BAC efficiency ratio (still wrong: 201% vs 61.65%) - planner. The graph holds the printed "Total revenue, net of interest expense" (revenue for a bank), but the planner read the phrase as an instruction and computed revenue minus interest expense itself. Not fixed on purpose: any prompt change re-plans every question; the fix (metric descriptions in the prompt, a bank-ratio dev example) is listed below.
  • Precision < 1 on T22 - operator design: related returns all 8 in-corpus competitors before the sector filter keeps 4, so 4 retrieved relation facts are not gold.
  • Weak spots the benchmark does not stress: shares outstanding found for 19/35 cover pages (multi-class tables, varied wording); headcount 32/35 (IBM, Qualcomm, Wells Fargo give no single total); Alphabet, Amazon, Meta and most banks name no competitors in Item 1, so competes_with is sparse there; segment revenues are line items, not facts linked to segment nodes; fiscal end dates are approximate where headers print only years.
  • Benchmark bias: the same AI drafted questions and built the parser. Mitigations: questions before the graph, gold from pages + XBRL, approved by Anmol before freezing, first frozen run reported. Still, 30 questions is small.

Improvements with more time

  • Planner: short metric descriptions in the prompt and a bank-ratio dev example (fixes T18); plan validation that refuses to recompute a printed total.
  • Held-out extraction test on filings not used for development (other companies, 10-Qs); LLM fallback for unmapped row labels (label -> metric id only).
  • Segment/dimension facts (IN_SEGMENT), customer-concentration % with relations, subsidiary-level entity resolution, Neo4j export.
  • A larger benchmark with questions written independently of the system builder, plus answer-confidence thresholds for abstaining.
